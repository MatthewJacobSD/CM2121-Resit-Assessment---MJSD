# CM2121 Eco Rescue FPS — Grade Target

## How RGU Grades This Module

| Target grade | Requirement |
|--------------|-------------|
| **A** | ≥50% of criteria at A; ≥75% at B or better; normally 100% at C or better |
| **B** | ≥50% of criteria at B or better; ≥75% at C or better; normally 100% at D or better |
| **C** | ≥50% of C or better; ≥75% at D or better |

**Word-limit penalty:** Exceeding page/word limits by >10% drops the grade one band.

| Deliverable | Limit | Penalty if exceeded |
|-------------|-------|---------------------|
| Design | 10 pages | Grade reduced one step |
| User testing | 2 pages | Grade reduced one step |
| Demonstration | 2 minutes max | Grade reduced one step |

## Criterion Breakdown

| Criterion | Weight | B Target | A Target |
|-----------|--------|----------|----------|
| Design | 20% | Good description of mechanics, assets, SFX/VFX, map | Thorough purpose, constraints, timeline; picture per asset; alternate asset list |

## Path to Grade B

### Design → B
- Contents page, SDG overview, project plan, task list
- One image per scanned object (8 images)
- Level map screenshot
- Mechanics, SFX, VFX sections filled
- Asset references and AI disclosure
- Stay within 10 pages

### Implementation → B
- 8 photogrammetry objects visible and textured
- FPS movement: walk, sprint, jump, crouch, slide, dash
- E pickup / throw into bin
- Scoring matches rules (+10/−20/−5, CRIT +40, 5-min timer)
- SFX audible on pickup, bin, trip, win/lose
- VFX: weather change, rain particles, skybox/lighting shift
- Clear mission on HUD
- SDG theme understandable without explanation

### User Testing → B
- Document 2 real sessions
- Replace placeholder tester names
- Note at least one bug found and fixed
- Mention photogrammetry assets tested
- Stay within 2 pages

### Demonstration → B
- Record MP4, max 2 minutes
- Narrate: game concept, SDG link, scanned assets, mechanics, SFX, VFX
- Show photogrammetry objects in gameplay
- Show at least one win or near-win run

## Path to Grade A

Everything in B, plus:

### Design → A
- Broad environment asset list; picture for each asset to be scanned
- Map of experience environment + alternate asset list
- Thorough purpose, goals, objectives, constraints, scope, timeline
- Actual mood board image (not text-only)
- Initial sketches (hand-drawn or digital)
- Constraints & scope subsection
- 1–2 pages of Blender before/after cleanup screenshots
- Alternate assets table

### Implementation → A
- Scans feel purposeful in layout
- Smooth, noticeable VFX transition
- Full ambience swap sunny ↔ rainy
- Win/lose/CRIT feedback clearly visible on HUD
- Both stumble and fall demonstrated
- All 6 plants + toys + bottles spawn
- No purple materials at submission

### User Testing → A
- Sessions cover wider scenarios: win path, lose path, toy penalty, time pressure
- All identified bugs marked resolved with method
- Explicit test: "do scanned plants read as real objects vs primitives?"
- Third scenario row, direct quotes, before/after column

### Demonstration → A
- Step-by-step photogrammetry pipeline: capture → Blender → Unity
- Each mechanic named on camera
- SFX/VFX audible and visible on recording
- 15-second Blender/scan montage
- Voiceover names each Freesound clip category
- End with perfect-win or high-score run
